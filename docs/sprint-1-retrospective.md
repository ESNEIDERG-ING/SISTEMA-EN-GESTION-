# Sprint 1 Retrospective

## Introducción

La retrospectiva permitió analizar el desarrollo del Sprint 1, identificando aspectos positivos, dificultades y acciones de mejora para los siguientes Sprints.

## ¿Qué funcionó bien?

El equipo logró organizar las historias de usuario de acuerdo con la capacidad disponible y establecer tareas técnicas relacionadas con el desarrollo en Java 17 y Spring Boot.

También se consideró la importancia de las pruebas automatizadas y de la revisión del código antes de integrar los cambios.

## ¿Qué dificultades se presentaron?

Durante el Sprint se presentaron dificultades relacionadas con la configuración del entorno de desarrollo, la organización de las tareas y la implementación de las funcionalidades.

Estas situaciones requirieron realizar ajustes y revisar nuevamente algunos elementos técnicos.

## ¿Qué se puede mejorar?

El equipo puede mejorar la distribución inicial de las tareas, establecer tiempos más claros para cada actividad y realizar revisiones técnicas desde las primeras etapas del Sprint.

También se recomienda mantener actualizada la documentación durante todo el proceso y no únicamente al finalizar el Sprint.

## Acciones de mejora

1. Revisar las tareas antes de iniciar cada Sprint.
2. Mantener actualizado el tablero de GitHub Projects.
3. Realizar revisiones de código de manera constante.
4. Ejecutar las pruebas automatizadas durante el desarrollo.
5. Registrar los impedimentos durante los Daily Scrum.
6. Mantener actualizada la documentación del proyecto.

## Conclusión

La retrospectiva permitió identificar oportunidades de mejora en la planificación, desarrollo, comunicación y seguimiento del proyecto. El equipo podrá utilizar estas conclusiones para mejorar la organización y ejecución de los siguientes Sprints.
